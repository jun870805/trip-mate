# AI 助手：架構、可用資料與授權

AI 助手整體架構、可查詢資料與授權範圍。其他 AI 規格見 [ai-chat-ui.md](ai-chat-ui.md)、[ai-model-provider.md](ai-model-provider.md)、[ai-email-feedback.md](ai-email-feedback.md)。

## 架構、可用資料與授權

- 新功能規劃參考 `docs/ai_agent_plan.md.md`；此檔為初步設計，技術選型及未確認提案不直接視為既定需求。
- AI 能力與聊天 UI 已接入；核心放在 `frontend/src/ai/`，目錄內 `README.md` 說明設計、設定、接入與移植。核心不依賴旅程、Sheets、路由、React 或 Vite env；選用的 `ai/ui` 僅依賴 React／通用契約，旅程橋接、dialog、共用元件與工具放在 `frontend/src/features/trip-ai/`。
- 已實作行程查詢、經確認增改刪／排序、檔案匯入與地圖搜尋連結補全的 API 與 UI。所有寫入先準備具體差異，確認時重驗當前授權與快照；未知結果／拒絕／衝突停止後續寫入，重新讀取後再操作。不以模型文字當作儲存成功。
- 共用提示詞獨立於 `frontend/src/ai/prompts/base-rules.ts` 的 `BASE_RULES`，由 Controller 匯入；旅程專用規則仍由 `features/trip-ai/index.ts` 注入 `system`，維護方式見 `frontend/src/ai/README.md`。`BASE_RULES` 限定只回答旅遊相關議題。程式碼、除錯、軟體開發等非旅遊需求須簡短委婉婉拒並引導回旅遊，不提供實質答案或呼叫工具；即使包裝為旅遊網站／景點爬蟲也不提供開發內容。混合問題只回旅遊部分，模糊主題先詢問，不因角色扮演或文件指令放寬範圍。
- 公積金、支出、進度問題目前僅可依每日行程內文／副標及航班／住宿備註的明確紀錄回答並註明來源；先查允許資料，沒有足夠資訊就回覆對應項目「尚未開放查詢」，不可宣稱無帳務／待辦或要求登入繞過。公積金交易／分攤、支出／收款、團員、待辦等其他表不提供給 AI，未來才擴充；預計金額或提醒不當成實際扣款、即時餘額或完成狀態。
- AI 航班／住宿及相關集合、接送、跨日安排問題，先用唯讀 `itinerary_get_travel_details` 交叉讀取此旅程全部航班、住宿與每日行程完整副標／內文。非空白的備註、行李說明及內文須分析與問題相關的提醒；多班次／多住宿逐筆辨識，不只挑第一筆，不假定使用者所搭班次。資料矛盾列出來源差異並請導遊確認，不自行補時間或推算飛行時長。規則放 `features/trip-ai/travel-context-rules.ts`，只傳公開欄位白名單及行程關聯 ID，不帶帳務、團員或額外欄；查詢仍使用已載入的公開資料，不增加 Sheets 寫入。行程搜尋包含內文。
- 範例來源強制唯讀且須有效導遊登入。AI 不新增帳務、團員或旅程目錄操作，也不提供航班／住宿增改刪。縮小不隱含批准；不保存輸入草稿、原始附件、待確認操作或正在寫入的動作。
