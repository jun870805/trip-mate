# Google Sheets 資料結構草案

狀態：第一階段已獲准實作。以下固定分頁與欄位已套用於網站及可匯入的範本；註明提案或待確認者仍保留討論空間。尚未直接寫入使用者的雲端試算表。

## 已確認的使用方式

- 高中同學每年一起出國，網站提供手機優先的旅遊資訊查閱。
- 入口選旅程，每趟旅程有自己的 Spreadsheet。
- 功能包含個人公積金餘額、飯店／航班／每日行程與 PDF 匯出、附日期的開團待辦進度。
- Google Sheets 是資料來源；指定導遊登入後可維護入口清單及旅程內團員、行程、帳務與待辦；一般團員維持唯讀。
- 公積金每趟獨立計算，旅程結束退還餘款；每項消費由實際參與者均分。
- 基本以當地幣別記帳，每趟旅程手動設定匯率，顯示位置不限定在公積金頁。
- 支出總表包含所有旅遊花費，含行前費用與公積金支付的旅途中消費。
- 行前費用須逐人、逐項追蹤是否繳款，允許多個項目合併收款；到店付款的住宿等費用由公積金支付，不重複向團員列為行前待收款。
- 匯率固定為「1 台幣 = 多少當地幣別」。
- 行前費用按實際刷卡的台幣金額記錄、分攤與收款，不以旅程匯率重算。
- 公積金儲值只收當地貨幣，不收台幣、不經換匯入帳。
- 一般團員無須登入；導遊清單編輯必須登入，僅允許指定 email 使用。

## 整體組織提案

另設一份「旅程目錄」Spreadsheet，只有「旅程清單」分頁。入口從這裡取得旅程名稱、日期及對應 Spreadsheet ID，避免每年開團都需要修改程式或環境變數。

每趟旅程從同一份範本複製，包含八個固定分頁：旅程設定、團員、公積金交易、公積金分攤、航班、飯店、每日行程、開團待辦。

為支援已確認的總表與收款需求，提議再增加「支出明細」「行前費用分攤」「收款明細」三個分頁，共十一個旅程分頁。這十一個分頁已用於第一版實作，後續可依實際需求調整。

目錄與每趟旅程供一般團員免登入讀取，資料來源需允許匿名檢視。已提前加入導遊 Google 登入及入口清單編輯；以 `VITE_GUIDE_EMAILS` 的 JSON 清單控制入口，並由 Google 檔案的實際編輯權限限制寫入。前端 email 名單或隱藏按鈕不能取代真正授權。其他導遊編輯功能暫不實作。

## 共用填寫規則提案

- 每個分頁第一列是固定欄位名稱，從第二列開始每列一筆資料；不合併儲存格、不插入額外標題列或小計列。
- 下方欄位標示「必填」之外，皆可留空；無資料的分頁保留欄位列即可。
- 所有業務 ID 使用「一個大寫英文字母＋三位補零流水號」，例如 `T001`、`M001`、`F001`，固定四個字元；超過 999 後接續 `T1000`，總長五個字元。超過 9999 前需另行確認擴碼。
- 網頁新增時預設自動編號，使用者可修改為格式正確、未使用的 ID；以對應資料範圍內的最大流水號加一，不以筆數或列號計算，不回填中間缺號。手動填寫試算表亦使用相同格式，讀取時會檢查主鍵及關聯 ID；舊格式若不符合需人工修正並同步關聯，不自動改名。
- 所有前綴共用 `frontend/src/data/id-rules.json`：T 旅程、M 團員、F 公積金交易、E 支出、R 收款明細、B 收款批次、A 航班、H 住宿、I 每日行程、P 開團待辦。關聯欄沿用來源 ID，不另編號；Google Spreadsheet ID 等外部識別碼維持 Google 原值。
- 每個分頁主鍵唯一。關聯欄位必須引用存在的 ID，不以姓名作為關聯鍵。
- 日期為 `YYYY-MM-DD`，時間為 24 小時 `HH:mm`；識別碼及日期時間欄位設為純文字。
- 航班與每日行程直接填各地當地時間；網站不要求輸入時差。旅程預設時區用於標題目的地時鐘與旅程日期判斷，既有活動時區覆寫欄保留相容。
- 金額欄只填數字，不附幣別、貨幣符號或手動輸入的千分位分隔符。
- 狀態欄使用固定下拉選單。空白列忽略；資料錯誤應顯示明確提示，不能默默當成零或漏掉。
- 範本版本放在旅程設定，第一版建議為 `1`。必要欄位可依名稱辨識，避免調整欄位順序後失效。
- 可預先在範本設定日期、數字、下拉選單及關聯 ID 的資料驗證，減少手動輸入錯誤。

## 各旅程 Spreadsheet

### 分頁：旅程設定

採一列設定資料，保留一般表格形式。

| 欄位 | 必填 | 用途 |
| --- | --- | --- |
| 結構版本 | 是 | 建議初版為 `1` |
| 旅程ID | 是 | 與旅程目錄對應 |
| 預設時區 | 是 | IANA 時區（如 `Asia/Tokyo`）或固定 UTC 時差（如 `UTC+9`、`UTC+05:30`；不套用夏令時間） |
| 記帳幣別 | 是 | 此趟旅程當地幣別，例如 `JPY` |
| 匯率基準幣別 | 是 | 固定為 `TWD` |
| 旅程匯率 | 是 | 手動輸入正數，定義為「1 TWD = 多少當地記帳幣別」 |
| 旅程說明 | 否 | 團員共用說明 |

匯率方向已確認。例如記帳幣別為 JPY、旅程匯率為 4.5，代表 1 TWD = 4.5 JPY；1,000 TWD 換算為 4,500 JPY，4,500 JPY 換算為 1,000 TWD。匯率放在旅程設定，由各頁共用，供跨幣別總表與參考顯示使用。行前費用保留實際刷卡台幣金額，公積金保留實收當地貨幣金額；更改匯率不影響行前應繳／已繳、公積金入帳／扣款或個人餘額。旅程結束按個人餘額退還當地貨幣，不換算成台幣退款。

### 分頁：團員

| 欄位 | 必填 | 用途 |
| --- | --- | --- |
| 團員ID | 是 | 建議同一人在不同旅程沿用相同 ID |
| 顯示名稱 | 是 | 暱稱即可 |
| 排序 | 否 | 團員顯示順序 |

餘額不手填於此表，避免與交易明細不一致。不存護照、證件或付款資訊。

### 分頁：公積金交易

一筆實際收支一列，記錄總額；透過下一個分頁記錄各團員分配的額度。

| 欄位 | 必填 | 用途 |
| --- | --- | --- |
| 交易ID | 是 | 交易唯一識別 |
| 日期 | 是 | 實際交易日期 |
| 類型 | 是 | 儲值／支出／退款／調整 |
| 項目 | 是 | 收支說明，例如共同晚餐 |
| 記帳金額 | 是 | 統一使用旅程記帳幣別，帶正負號 |
| 備註 | 否 | 更正或其他補充說明 |

符號規則：儲值為正數、支出與退還團員餘額為負數、調整可正可負但須有原因。「退款」暫指公積金退還團員；商家退費可先以正數調整記錄。是否需要區分商家退費，後續依實際流程確認。

公積金儲值直接填入實際收到的當地貨幣金額，不提供台幣儲值或換算入帳流程。此表所有數字均以旅程當地幣別記錄，退款亦直接退還當地貨幣。

### 分頁：公積金分攤

| 欄位 | 必填 | 用途 |
| --- | --- | --- |
| 交易ID | 是 | 對應公積金交易 |
| 團員ID | 是 | 對應團員 |
| 個人金額 | 條件必填 | 儲值／退款／調整時必填；支出時由參與者均分規則計算，不手填不同分攤額 |

支出交易在此表每列表示一位實際參與者，只填交易 ID 與團員 ID 即可；不參與者不建立該交易的分攤列。儲值、退款與調整則填入對各團員餘額的實際增減額。

同一交易與團員的組合不可重複。每筆支出至少有一位參與者，分攤金額依下述規則計算；儲值、退款與調整的最終個人金額加總必須等於記帳金額；支出允許因同額向上取整而使扣款合計高於實際消費，多出的部分列為公共餘款。每個人的餘額為其所有最終個人金額加總。

示例（僅示範資料規則）：兩人各儲值 3,000，一起消費 800，平均分攤時各扣 400，兩人的餘額各為 2,600；若其中一人未參加該次消費，就不建立他的分攤列。

均分規則已確認：使用記帳幣別最小單位，每位參與者同額向上取整。例如 1,000 JPY 分三人為 334、334、334 JPY，分攤合計為 1,002 JPY，2 JPY 尾差保留為公共餘款，之後再決定用途。實際消費保留為 1,000 JPY，並列出分攤合計與尾差；不可偽造店家實收或將尾差重複列為消費。金額計算使用最小單位整數，不直接以浮點數判定加總相等。

每趟公積金獨立，結束時按個人餘額退還當地貨幣；實際退還後記錄退款交易，不能只因旅程結束便直接把餘額歸零。若餘額不足，不顯示為可退款，提示待補繳；第一版不阻擋顯示手動維護的負餘額。個人代墊後報銷仍待確認。

### 分頁提案：支出明細

此頁是整趟旅程支出總表的資料來源，包含機票、飯店等行前費用及公積金支付的旅途中消費。

| 欄位 | 必填 | 用途 |
| --- | --- | --- |
| 支出ID | 是 | 支出唯一識別 |
| 日期 | 是 | 此筆費用的日期 |
| 項目 | 是 | 費用說明 |
| 分類 | 是 | 航班／住宿／交通／餐飲／活動／其他 |
| 金額 | 是 | 原始費用的正數金額 |
| 幣別 | 是 | 行前收款固定 TWD；公積金支出固定旅程當地幣別 |
| 支付方式 | 是 | 行前收款／公積金 |
| 公積金交易ID | 否 | 若由公積金支付，關聯對應的支出交易，避免重複計算 |
| 備註 | 否 | 說明 |

金額以原幣別保留，顯示整趟總額時使用旅程匯率統一換算為當地幣或台幣；不可直接加總不同幣別。換算總額應標明是按設定匯率換算的參考數字。

行前費用的金額直接使用實際刷卡台幣金額，不從外幣標價推算應收款。總表提案同時顯示「行前支出 TWD」「公積金消費（當地幣）」及換算後的整趟參考總額，清楚區分實際帳務與換算值。

支付方式為公積金時，必須關聯對應支出交易，並以其當地幣別支出金額為準；不在行前費用分攤新增待收款。這適用於到店支付的房費等消費。

總額規則：支出總額來自支出明細，公積金交易只作資金流與餘額計算；同一筆公積金消費不得重複計入整趟花費。儲值與旅程結束退還餘額不算旅遊消費。已收錢指團員行前繳款，不代表已向店家付款；是否另追蹤對外付款狀態，尚未確認。

### 分頁提案：行前費用分攤

一筆行前支出中，一位應繳團員一列。行前分攤與公積金扣款分開維護，避免重複收費。

| 欄位 | 必填 | 用途 |
| --- | --- | --- |
| 支出ID | 是 | 僅能關聯支付方式為行前收款的支出 |
| 團員ID | 是 | 此人需繳此項費用 |
| 應繳金額 | 是 | 此人的應繳台幣金額，由實際刷卡金額分攤 |

支出 ID 與團員 ID 組合唯一。費用分攤總額須與該筆支出總額一致。第一版保留每人實際應繳額，以便處理機票價格或房型不同的情況；公積金則依已確認規則自動均分。

### 分頁提案：收款明細

一筆收款分配到一位團員的一項行前費用一列。一次收多項費用時，新增多列並使用相同收款批次 ID，保留逐項追蹤能力。

| 欄位 | 必填 | 用途 |
| --- | --- | --- |
| 收款明細ID | 是 | 每列唯一識別 |
| 收款批次ID | 是 | 同一次繳款的各項分配共用 ID |
| 收款日期 | 是 | 實際收到款項的日期 |
| 團員ID | 是 | 繳款團員 |
| 支出ID | 是 | 此次收款分配的行前費用 |
| 實收金額 | 是 | 本列分配到該項的實收台幣金額 |
| 備註 | 否 | 補充說明 |

所有行前收款固定為台幣。同一批次暫提議限定同一團員與日期。一個批次可包含多個費用項目，其各列金額加總代表此批次收款總額，不能在每列重複填整筆轉帳金額。此表不記錄公積金儲值，公積金收到的當地貨幣另記於公積金交易。

示例（僅示範資料）：某團員一次繳機票 8,000 TWD 與行前住宿 3,000 TWD，共 11,000 TWD；收款明細記兩列、共用同一批次 ID，兩筆費用均能顯示此人已繳。

第一版每人每項「實收合計」對照「應繳金額」，產生未收／部分已收／已收齊狀態；超收會提示核對。行前退款與對外付款等延伸流程尚待確認。收款分配必須對應已存在的行前費用分攤，不能拿公積金消費建立另一筆待收款。

第一版提案假設為全團共用航班；分批搭機是否需要記錄乘客名單，待確認。

第一版提案不記錄訂房代碼與個人房間配置。

### 分頁：每日行程

一個活動一列，依日期、排序及開始時間顯示。

| 欄位 | 必填 | 用途 |
| --- | --- | --- |
| 行程ID | 是 | 活動唯一識別 |
| 日期 | 是 | 當地活動日期 |
| 開始時間 | 否 | 留空時不顯示指定時間 |
| 結束時間 | 否 | 預設同日；跨日活動建議拆列 |
| 時區 | 否 | 保留舊資料相容，網站新增活動時留空；活動以當地時間呈現 |
| 標題 | 是 | 活動名稱 |
| 類型 | 是 | 景點／餐飲／交通／住宿／自由活動／其他 |
| 地點 | 否 | 場所名稱或地址 |
| 地圖網址 | 否 | 導航連結 |
| 說明 | 否 | 集合、交通或注意事項 |
| 航班ID | 否 | 關聯航班，避免重複填寫航班細節 |
| 住宿ID | 否 | 關聯飯店，避免重複填寫住宿細節 |
| 排序 | 是 | 同一天內的明確順序，建議用 10、20、30，方便插入 |

PDF 提案包含旅程名稱與日期、航班、飯店及按日排列的行程；不預設包含公積金或開團待辦。PDF 的版面與匯出範圍仍待確認。

### 分頁：開團待辦

| 欄位 | 必填 | 用途 |
| --- | --- | --- |
| 任務ID | 是 | 待辦唯一識別 |
| 事項 | 是 | 例如訂機票、確認飯店 |
| 分類 | 否 | 航班／住宿／交通／活動／其他 |
| 狀態 | 是 | 待辦／進行中／已完成／已取消 |
| 截止日期 | 是 | 此事項預計完成日期 |
| 完成日期 | 否 | 已完成時必填；其他狀態留空 |
| 負責團員ID | 否 | 對應團員，初期至多一位負責人 |
| 備註 | 否 | 補充說明 |
| 排序 | 否 | 自訂顯示順序 |

提案：進度為「已完成數 ÷ 未取消任務總數」；沒有未取消任務時顯示「尚無待辦」，不顯示 100%。逾期判斷使用旅程預設時區，已完成／已取消不視為逾期。

## 每次開團的維護流程提案

1. 複製範本 Spreadsheet，命名新旅程。
2. 設定旅程 ID、時區、當地記帳幣別與手動匯率，填入此次團員。
3. 在目錄的旅程清單新增一列，填上新 Spreadsheet ID、旅程名稱與日期。
4. 在各分頁維護資料；沒有內容的分頁保留標題列。
5. 發布前檢查權限、ID 關聯、日期與公積金收支／分攤總額。

範本本身不放入真實交易；若複製上一趟旅程，必須清空舊交易、舊分攤與其他不沿用的內容。

## 優先待確認

1. 個人代墊、商家退費是否需要獨立流程。
2. 是否需要追蹤對店家付款狀態（現有收款只代表團員是否繳款）。
3. 分批航班、PDF 版面、公共餘款日後使用等後續需求。

其餘後續討論：負餘額、代墊、商家退費、分批航班、PDF 匯出範圍與開團日期的實際定義。已確認每趟獨立退款、實際參與者均分、當地幣別與手動匯率（1 TWD = 多少當地幣）、第一階段免登入、第二階段指定 email 的導遊登入功能，以及全旅程支出、行前逐人逐項與合併收款、到店費用由公積金支付。


## 可使用的檔案

- 固定欄位：`frontend/src/data/schema.json`。
- 匯入範本：`frontend/public/templates/旅程目錄範本.xlsx` 與 `每趟旅程範本.xlsx`。
- 完整範例：`frontend/public/templates/範例旅程.xlsx`（僅供示範）。
- Google Apps Script：`frontend/public/templates/建立Google試算表範本.gs`，只建立新檔，不修改既有檔案或共用權限。
- 重建範本：`python3 scripts/generate_templates.py`。
- 操作說明：`docs/setup-sheets.md`。

時間輸入更新：網站新增／編輯航班只填當地日期時間，新增值如 `2027-05-01T09:00:00`，不附加或猜測 UTC 偏移。舊的含偏移值仍相容。每日行程的時區欄保留結構相容，但網站不提供該欄輸入；旅程標題改以台灣與目的地即時鐘面時間呈現。
