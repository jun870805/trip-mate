# 現有功能檢查與優化建議

檢查日期：2026-10-27。以下為建議，尚未經使用者確認，不代表新增需求或實作授權。本輪未修改網站功能。

檢查範圍：旅程目錄、總覽、行程與 PDF、公積金、支出與收款、開團進度、導遊登入、旅程清單編輯、試算表建檔與共用、國家／幣別／時區、範本。

## 驗證結果

- 100 項資料與 API 模擬測試通過；資料層行數覆蓋率 99.43%，不代表瀏覽器互動或真實 Google API 的覆蓋率。
- 正式建置、React 靜態畫面渲染檢查通過。
- 三份 Excel 範本結構檢查、Apps Script 模擬建立檢查通過。
- 程式檢查涵蓋均分向上取整、公共尾差、公積金與總表關聯、逐人逐項收款、免登入權限錯誤分類、導遊寫入與 ID 驗證。
- 本輪沒有執行真實 Google OAuth／Drive 寫入或手機瀏覽器操作；PDF 實際分頁、登入彈窗及 RWD 仍需實機驗證。

## 優先改善

### 1. 資料錯誤不應阻擋無關功能

位置：`frontend/src/data/portal.ts` 的 `parseTrip`，`frontend/src/App.tsx` 的 `TripLoader`。

目前全部十一個分頁一起讀取與驗證。已用範例副本確認：公積金金額填錯時，`parseTrip` 直接拒絕整趟旅程，航班、飯店、行程亦無法查看。目錄任一列錯誤也會阻擋整份清單。

建議將行程、帳務與待辦的驗證分開呈現；帳務內的公積金、分攤、支出與收款仍須共同核對，不能把錯誤資料當成零金額繼續計算。導遊看到修正位置，一般團員看到受影響功能暫不可用。

### 2. 錯誤訊息的列號有實際偏差

位置：`frontend/src/data/portal.ts:98`。

資料列先排除空白列，再用索引加二產生原始列號。已確認：標題後插入一空白列，第三列填錯 ID，錯誤卻指出第二列。部分金額錯誤也只有「金額格式錯誤」，缺乏分頁、原始列號與欄位。

建議保留原始列號，統一提供「分頁／列號／欄位／原因」。導遊可提供開啟對應資料位置的連結；一般模式維持簡短提示。

### 3. 建檔與編輯流程提供草稿復原

位置：`frontend/src/components/CatalogEditor.tsx`、`frontend/src/components/TripFileCreator.tsx`。

目前關閉、取消或按 Escape 會直接離開表單；草稿與已建立檔案資訊只存在元件記憶體。建檔成功但尚未加入清單時，關閉表單後仍可去 Drive 找回檔案，但網站沒有接續完成的入口。

建議有變更時提醒再離開，並在同一瀏覽分頁暫存草稿與「已確定建立成功」的檔案 ID，讓使用者接續加入清單。Access token 繼續只放記憶體；結果不明的建檔請求不能自動重送。

### 4. 首頁錯誤文案與旅程內一致

位置：`frontend/src/App.tsx:204`。

旅程內已針對導遊與一般觀看者顯示不同說明，但首頁讀取目錄失敗仍直接對一般人顯示 Google Sheets、API Key 等技術錯誤。

建議首頁也依模式分流：一般人看到「目前無法載入旅程，請稍後再試」，導遊才看到原始錯誤與設定方式。

## 各功能的後續建議

| 功能 | 目前觀察 | 建議 |
| --- | --- | --- |
| 旅程清單 | 已有排序與四種狀態 | 歷年旅程變多時，增加「進行中／已結束」篩選與名稱搜尋；目前僅少量旅程可延後。 |
| 總覽／更新資料 | 更新時清空整份資料，且沒有最後成功讀取時間 | 顯示更新時間與更新中狀態。若保留舊畫面，必須清楚標示；權限被拒絕時仍立即清除內容，不能用舊快取繼續顯示。 |
| 行程 | 預設全部日期，重新進入需找當天 | 旅途中預設顯示目的地今天的行程；保留全部日期與其他日期。飯店電話可提供直接撥號。需確認預設日期行為。 |
| PDF | 現在固定全部行程，透過瀏覽器列印 | 保留現有預設，再提供全部／目前日期的選擇；驗證長文字、跨頁、地圖連結與手機匯出。是否擴大匯出範圍尚待確認。 |
| 公積金 | 已區分實際支出、分攤合計與公共尾差 | 增加明確的「個人餘額合計＋公共餘款＝現金餘額」對帳列；結束時列出待退／待補清單。不得自動決定公共餘款用途。 |
| 支出與收款 | 已有逐人逐項狀態；合併繳款靠批次 ID 關聯 | 增加每人的總應繳、總已繳、總未繳與超收金額，並支援只看未收齊。合併繳款以日期、項目與合計為主，批次 ID 放詳細資訊。 |
| 開團進度 | 狀態篩選、完成度與逾期提醒已具備 | 增加「即將到期」篩選；總覽可顯示最近幾項待辦。頁面若跨午夜保持開啟，可更新日期，避免逾期標示停留在前一天。 |
| 導遊登入 | SDK 目前在一般訪客開站時也載入 | 登入 SDK 改由需要登入時載入或預載失敗時不打擾一般訪客；登入失敗由使用者操作後再提示。保留 token 僅存記憶體。 |
| 清單編輯 | 有快照衝突檢查，但不是原子鎖 | 目前單一導遊可先維持；遇衝突時保留草稿、提供重新載入與比較，避免只能取消重填。若未來多人同時寫入，再評估後端衝突控制。 |
| 建立檔案／共用 | 已保留部分成功結果，支援重試設定 | 儲存入口前提供公開讀取檢查，確認實際可讀與旅程 ID 對應；私人檔案仍允許保存，但導遊須看見未開放狀態。不能自動替使用者開共用。 |
| 國家、幣別、時區 | 已支援搜尋、多選項與 UTC 固定時差 | 國家帶入與手動輸入可切換且不丟值；修改國家／幣別後清空匯率時顯示簡短提醒，減少「數值怎麼不見」的困惑。 |
| 手機與無障礙 | 團員卡片已有 aria-pressed，日期／待辦篩選只有外觀選取樣式 | 日期及待辦按鈕補上可辨識的選取狀態；實機確認國家鍵盤選擇、對話框焦點、長名稱、橫向日期列與列印。 |
| 範本與維護 | schema 與範本來源共用，現有檢查通過 | 把範本、渲染與既有資料測試納入同一個完整檢查指令，避免未來只跑單元測試而漏查產物。 |

## 建議實作順序（待確認）

1. 修正錯誤列號與補足導遊錯誤定位、統一首頁的一般模式文案。
