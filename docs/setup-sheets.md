# 建立與填寫試算表

網站有一份「旅程目錄」，每趟旅行各自再有一份「旅程試算表」。分頁名與第一列欄位名稱須保持範本原樣；欄位可以換順序，但不要刪除或重複。入口清單與旅程內的團員、行程、帳務及待辦，可由指定導遊登入後透過網頁維護，也保留手動修改 Google Sheets 的方式。各旅程檔案須另授予導遊編輯權。

## 1. 建立範本

方式一：將 `frontend/public/templates/旅程目錄範本.xlsx`、`每趟旅程範本.xlsx` 分別匯入 Google Sheets，並轉換為 Google 試算表格式。

方式二：到 https://script.google.com/ 建立專案，貼上 `frontend/public/templates/建立Google試算表範本.gs` 全文，選擇 `createTripMateTemplates` 執行。首次執行需要你在 Google 畫面授予建立試算表的權限。執行記錄會顯示兩份新檔案網址；此程式不會改寫既有檔案，也不會自動公開檔案。

保留一份乾淨的每趟旅程範本，開團時複製範本，而不是複製含上一趟帳務的檔案。

## 2. 填旅程目錄

「旅程清單」一列一趟，以下內容僅為填寫示例：

| 旅程ID | 旅程名稱 | 目的地 | 開始日期 | 結束日期 | 試算表ID | 旅程狀態 | 封面圖片網址 | 排序 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| T001 | 大阪同學旅行 | 日本・大阪 | 2027-05-01 | 2027-05-03 | 填此趟旅程檔案的實際ID | 規劃中 | 可留空 | 10 |

網址中的 `/d/` 與 `/edit` 之間是 Spreadsheet ID，不是分頁的 `gid`。環境設定填「旅程目錄」的 ID；每一列的試算表ID填該趟旅程檔案的 ID，兩者不要混用。

## 3. 填這趟的設定與團員

透過網站新增旅程時，旅程 ID 會自動產生（例如 `T001`），新增時可修改此預設值，但必須符合格式且不能重複。請複製該值到旅程設定，不要另取一個不同的 ID。其他業務 ID 也採單一大寫英文字母加三位數，如 `M001`、`F001`；超過 999 後使用四位數流水號，如 `T1000`。Google 的試算表 ID 不受此規則影響。

「旅程設定」只有一列設定：

- 結構版本填 `1`。
- 旅程ID 與目錄相同，例如 `T001`。
- 預設時區填 `Asia/Tokyo` 等 IANA 時區，或 `UTC+9`、`UTC-5`、`UTC+05:30` 等固定時差；固定時差不套用夏令時間。
- 記帳幣別填目的地當地幣別，例如 `JPY`。
- 匯率基準幣別填 `TWD`。
- 旅程匯率填「1 台幣可換多少當地幣」，例如 `4.5`。此數字只供示例，請填自行決定的實際旅程匯率。

「團員」每人一列，團員ID不可重複。顯示名稱填暱稱即可；不要加入護照等不適合公開的資訊。

## 4. 行前費用與收款

以兩人共同刷卡買機票共 20,000 台幣為例：

1. 「支出明細」新增一筆 `E001`，金額填 `20000`、幣別填 `TWD`、支付方式填 `行前收款`、公積金交易ID留空。
2. 「行前費用分攤」新增兩列，支出ID都填 `E001`，各填團員ID及實際應繳台幣金額；例如各 `10000`。加總須等於支出。
3. 收到團員付款後，才在「收款明細」記錄實收台幣金額，關聯對應支出及團員。
4. 機票與住宿一起收時，分開記各項的實收分配金額，但使用同一收款批次ID、團員與收款日期。不要每列都填整筆轉帳金額。

網站會計算每人各項的未收／部分已收／已收齊；超收會提示核對。此狀態代表團員是否繳款，不代表店家是否已收到款項。

## 5. 公積金儲值、消費與退餘款

例如三人各繳 2,000 日圓：

1. 「公積金交易」新增 `F001`，類型 `儲值`、金額 `6000`。
2. 「公積金分攤」新增三列，交易ID都填 `F001`，各填團員ID、個人金額 `2000`。

之後三人一起吃飯實際花 1,000 日圓：

1. 「公積金交易」新增 `F002`，類型 `支出`、金額填 **`-1000`**。
2. 「公積金分攤」新增三列，填 `F002` 與三位實際參與者的團員ID，**個人金額留空**，網站會各扣 334，合計扣款 1,002，2 日圓留為公共餘款。
3. 「支出明細」新增對應的唯一一筆，金額填正數 `1000`、幣別 `JPY`、支付方式 `公積金`、公積金交易ID填 `F002`。此列用來納入支出總表，網站不會重複扣個人餘額。
4. 到店支付的住宿也用同樣方式，不再建立行前待收款。

結束退還某團員 1,666 日圓時，在公積金交易記類型 `退款`、金額 `-1666`，公積金分攤填該團員與 `-1666`。未實際退還前不要先把餘額歸零。公共餘款不自動分給個人。

「調整」需填備註，且個人分攤合計要與交易相同；可用於有說明的資料更正，但不代表已提供代墊或商家退費流程。

## 6. 行程與開團進度

- 航班一個航段一列。出發／抵達時間填各地的當地日期時間，例如 `2027-05-01T09:00:00`；也相容舊的含時區格式，例如 `2027-05-01T09:00:00+08:00`、`2027-05-01T12:30:00+09:00`，並使用實際航班資訊。
- 飯店一次住宿一列，填當地入住／退房日期、地址。房費是行前收款或到店使用公積金，由支出明細決定。
- 每日行程一個活動一列，日期 `YYYY-MM-DD`，時間 `HH:mm`，排序可用 10、20、30。時間可留空；跨日活動拆列。網站不需填時區欄；活動時間直接視為當地時間。
- 航班ID／住宿ID可連到對應分頁，網站與 PDF 顯示關聯資訊。
- 開團待辦可選待辦／進行中／已完成／已取消。填截止日期；只有已完成狀態填完成日期。完成度不計入已取消項目。
- 沒資料的分頁仍需保留第一列欄位，不能直接刪分頁。
- 日期、ID、航班日期時間建議維持範本的純文字格式；避免 Google 自動改成其他日期格式。

## 7. 讓網站讀取

1. 啟用 Google Sheets API，建立限制網站來源與 API 用途的瀏覽器 API Key。
2. 旅程目錄及各旅程試算表的共用皆設定「知道連結的任何人 → 檢視者」。第一階段免登入，公開資料不應包含私密資訊。
3. 編輯 `frontend/.env.local`：

   ```dotenv
   VITE_GOOGLE_SHEETS_API_KEY=你的APIKey
   VITE_GOOGLE_SHEETS_CATALOG_ID=旅程目錄ID
   ```

4. 重新啟動 `npm run dev`。API Key 的 HTTP referrer 須包含開發伺服器的實際網址與埠。
5. 選旅程後即可讀取；在 Google Sheets 修改資料後，按「更新資料」重新載入。資料驗證失敗會顯示原因，不會自動改用範例數據。

舊的 `VITE_GOOGLE_SHEETS_SPREADSHEET_ID` 暫保留作為目錄 ID 備援，但單張任意範圍的試算表預覽已改為固定分頁應用。網站不會自動轉換舊檔結構；只有導遊明確儲存時才更新旅程清單。

## 8. 使用網頁編輯旅程清單

依 README 的「導遊登入與旅程清單編輯」建立 OAuth Web Client ID，並在 `.env.local` 設定 `VITE_GOOGLE_CLIENT_ID` 與 `VITE_GUIDE_EMAILS='["你的email@gmail.com"]'`。允許的帳號須同時具有目錄試算表的實際編輯權限。

重新啟動後，按「導遊登入」，就能在入口新增、編輯或移除旅程紀錄。這會寫入目錄檔案，不會修改各趟旅程的內容。一般團員仍可免登入查看。


## 9. 不先手動建檔，直接由網站建立

Google Cloud 啟用 Google Drive API，重新登入授予檔案權限後，在「新增旅程」展開「建立空白旅程試算表」。可用中文、英文或國家代碼搜尋國家，自動帶入單一幣別與時區；多個選項時自行選擇，並可手動調整。填妥匯率後，按「建立並填入 ID」即可建立十一個分頁及欄位。旅程 ID 與基本設定已自動寫入，無須再手動複製；其他業務資料保持空白。接著按表單「儲存」加入入口。共用設定失敗時保留已建檔案，請重試共用或手動開放檢視。
